## 1. 결론

Claude 리뷰의 제품 리셋 방향과 저장소 재사용 권고를 수용한다.

제품은 현재 저장소를 폐기하지 않고 다음 방식으로 재정비한다.

1. 인증·승인·수집·DB·Cron 기반은 재사용한다.
2. 과도하게 확장된 기능은 먼저 UI·라우트·Cron에서 비활성화한다.
3. 기업·기술·정책·투자 4축을 공통 카드로 제공한다.
4. 중요 체크·메모·묶음·검색을 제품 중심으로 복원한다.
5. 시장·거시경제 대시보드는 사용자가 확정한 필수 기능으로 유지한다.
6. 고정 섹터 구조는 도입하지 않는다.

## 2. 사실관계 정정

Claude의 “GitHub main에 실제 코드가 없다”는 지적은 핵심적으로 맞지만 표현을
다음과 같이 정정한다.

- `origin/main`: 초기 커밋 `625d9cc`
- 현재 구현 브랜치: `codex/round1-auth`
- 현재 구현 및 원격 브랜치 HEAD: `174ef22`
- 현재 구현 브랜치는 `origin/main`보다 14개 커밋 앞섬

따라서 실제 코드는 원격 GitHub에 존재하지만 `main`에 통합되지 않은 상태다.
Stage 0에서 PR 또는 명시적 통합 절차를 거쳐 `main`을 배포 기준선과 일치시켜야 한다.

## 4. 수정 수용한 권고

### 경제지표 5종

1차 지표는 다음으로 축소한다.

- USD/KRW
- KOSPI
- KOSDAQ
- 한국 기준금리
- 소비자물가

S&P 500, NASDAQ, GDP 성장률, 고용·실업 지표는 공급자와 운영 안정성을 확인한 뒤
추가한다.

축소는 대시보드의 중요도를 낮추는 것이 아니라, 신뢰할 수 있는 데이터부터
제공하기 위한 범위 조정이다.

### 비활성 테이블

즉시 삭제하지 않는다는 권고를 유지한다. 코드와 스키마에는 deprecated 사유와
삭제 검토 시점을 기록하고, 새 기능에서 참조하지 않도록 한다.

## 5. 수용하지 않은 권고

### 독립 `/dashboard`를 MVP 선택으로 강등

수용하지 않는다.

사용자는 대시보드와 거시지표가 반드시 필요하다고 반복해서 확정했다. `/today`의
간략 경제 현황과 별도로 출처·기준일·최근값·수집 상태를 확인하는 `/dashboard`는
MVP 필수로 유지한다.

단, 복잡한 비교 그래프·정규화·자동 변곡점 기능은 후속으로 둔다.

### 접근 통제 복원을 독립 작업으로 수행

수용하지 않는다.

사용자 결정에 따라 접근 정책을 새로 개발하거나 복원하는 작업은 REBOOT 후속 순서에서
제외한다. 기존 인증·승인 기능은 재사용하고 다른 변경으로 기존 동작이 깨지지 않는지만
회귀 검증한다.

### 지식 관리 상태 확장

개인 숨김과 읽음 상태는 제외한다. 지식 관리는 다음 세 기능으로 제한한다.

- 중요 체크
- 사용자별 카드당 메모 하나
- 제목과 카드 목록만 갖는 묶음

제품 모델에 관한 주요 결정은 이번 리뷰로 잠정 확정했다. 구현 전에 남은 결정은
다음 네 가지다.

1. 5개 경제지표 각각의 공식 데이터 공급자와 이용 조건
2. 기존 논문·기업 명부 데이터의 장기 보존 또는 삭제
3. 기존 정보가치 점수의 완전 숨김 또는 단순 정렬 보조값 유지
4. `codex/round1-auth`를 `main`에 직접 통합할지 PR 검토 후 통합할지
