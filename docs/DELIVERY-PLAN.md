# 전체 개발 실행계획과 역할 분담

작성일: 2026-07-24  
상태: 개발 착수안

---

## 1. 전체 개발 범위

제품은 여섯 영역으로 나눠 개발한다.

```text
1. 기반·인증
2. 데이터 수집 워커
3. 데이터 처리·저장
4. 프론트엔드
5. 메모·묶음
6. 배포·운영
```

Claude와 Codex가 프론트엔드·백엔드를 각각 하나씩 독점하는 구조로 나누지 않는다. 그러면 서로 다른 설계가 생기고 통합 비용이 커진다.

역할은 다음과 같이 나눈다.

- **Claude:** 각 영역의 설계·불변조건·수용 기준·리뷰
- **Codex:** 전체 코드 구현·테스트·통합·실행
- **사용자:** 제품 선택·외부 계정 설정·결과 승인

## 2. 역할의 기본 원칙

### Claude

- 무엇을 만들어야 하는지 구조화
- 데이터 모델과 실패 시나리오 검토
- 화면 정보 구조와 사용자 흐름 검토
- 구현 결과의 보안·정합성 리뷰
- 직접 애플리케이션 코드를 병렬 수정하지 않음

### Codex

- 저장소와 브랜치 관리
- 프론트엔드·백엔드·워커 구현
- 마이그레이션과 테스트 작성
- 로컬 실행과 브라우저 검증
- Claude 의견의 수용·보류·반박 판단
- 전체 코드를 하나의 동작하는 제품으로 통합

### 사용자

- 어떤 제품을 만들지 최종 결정
- 외부 서비스 계정과 비밀값 준비
- 실제 카드와 화면이 유용한지 판단
- 배포·비용·외부 데이터 저장 승인
- 코드를 직접 작성할 필요는 없음

## 6. 사용자 작업을 최소화하는 방식

- 계정 생성 화면까지 이동

사용자만 할 수 있는 것:

- 외부 계정 로그인
- OAuth·DB·배포 권한 승인
- 결제 또는 비용 발생 승인
- 제품 가치와 디자인 최종 판단
- 비밀값 직접 입력

## 7. 매 라운드의 협업 방식

```text
1. Claude: 설계·위험·수용 기준 검토
2. Codex: 구현·테스트
3. Claude: 완성된 diff 리뷰
4. Codex: 리뷰 반영·통합
5. 사용자: 실제 화면과 데이터 승인
```

### 사용자에게 보고하는 내용

각 라운드 완료 시 Codex가 다음을 한 번에 보여준다.

- 만들어진 기능
- 실제 화면
- 테스트 결과
- Claude 리뷰와 반영 여부
- 알려진 한계
- 다음 라운드에서 사용자가 결정할 것
