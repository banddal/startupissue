# 개발 계획과 역할

## 전체 순서

| Round | 결과 |
|---|---|
| 1 | Google 로그인·관리자 승인·빈 오늘 화면 |
| 2 | RSS 기사 한 건이 카드로 표시 |
| 3 | 정부 공고·AI 요약·정보가치 |
| 3.5 | 생태계 지표 4종 현재값·전기 대비 변화량 |
| 4 | 검색·기업/주제 타임라인·원문 보관 |
| 5 | 메모·카드 묶기 |
| 5.5 | 지표 그래프·시장/거시 현황·구간 묶음 |
| 6 | 자동 수집·베타 배포 |

## 역할

### Claude

- 데이터 모델과 실패 시나리오 검토
- 보안·권한·정보 구조 검토
- 수용 기준 작성
- 완성된 diff 리뷰

### Codex

- 저장소 관리
- 프론트엔드·백엔드·워커 구현
- 마이그레이션과 테스트
- 브라우저 검증과 배포
- Claude 리뷰 반영과 통합

### 사용자

- 제품 우선순위와 디자인 승인
- 외부 서비스 계정 연결
- 비밀값 직접 입력
- 실제 카드 품질 평가
- 비용과 배포 승인

## Round 1

목표:

> 승인된 사용자만 빈 오늘 화면을 본다.

완료 조건:

- 첫 로그인 사용자는 pending
- admin이 active·rejected·suspended 변경
- active만 today 접근
- 상태 변경은 다음 요청부터 반영
- 페이지·Server Action·관리자 기능의 권한 검사
- lint·typecheck·test·build 통과

## Round 2

목표:

> RSS 기사 한 건이 수집되어 화면에 보인다.

구현:

- RSS adapter 하나
- Node CLI worker
- 원천 멱등 저장
- 수집 실행 이력
- 카드 생성
- 카드 목록과 상세

사용자 결정:

- 첫 RSS 매체
- 좋은 카드와 불필요한 카드의 표본 평가

## Round 3 이후

- 정부 공고 소스
- AI 요약과 분류
- 정보가치 정렬
- Round 3.5 생태계 상황판 v1
- 검색과 누적 타임라인
- Private R2 아카이빙
- 메모·묶음
- Round 5.5 상황판 그래프와 시장·거시 지표
- 배포와 운영

세부 의존성, 결정 게이트와 수용 기준은 `docs/DELIVERY-PLAN.md`를 기준으로 한다.

