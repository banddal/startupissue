# Startup Issues — 제품 재정의 PRD

버전 0.3 Draft · 최초 작성 2026-07-31 · 사용자 범위 수정 2026-08-01  
상태: 기업·기술·정책·투자 4축 반영 · 사용자 최종 승인 전  
기존 문서: `docs/PRD.md`와 별도로 유지하며, 승인 전에는 기존 문서를 대체하지 않는다.

---

## 1. 문서 목적

현재 구현은 기업·기술·정책·투자 정보를 매일 모니터링하고 중요한 지식을 축적하려던
초기 목적에서 벗어나, 기업 명부·정보가치 평가·생태계 숫자·논문 저장소 등 주변
기능이 과도하게 확장되었다.

이 문서는 제품을 처음 목적에 맞게 다시 정의한다.

- 고정된 산업 섹터를 제품 진입 조건으로 요구하지 않는다.
- 기업 정보, 기술 정보, 정책 정보, 투자 정보를 동등한 핵심 수집 축으로 둔다.
- 시장·거시경제 대시보드를 정보 해석의 필수 배경으로 제공한다.
- 사용자가 중요한 지식을 체크하고 메모하고 묶어 다시 활용하게 한다.
- 사용자 2~3명의 내부 도구에 맞게 기능과 데이터 구조를 단순하게 유지한다.

## 2. 제품 정의

### 2.1 한 문장

> 기업·기술·정책·투자 정보를 매일 자동으로 모니터링하고, 시장·거시경제 현황과 함께
> 확인하며, 중요한 지식을 체크·메모·묶음으로 축적하는 내부 인텔리전스 도구.

### 2.2 핵심 가치

1. **놓치지 않는다.**  
   흩어진 기업·기술·정책·투자 정보를 매일 한곳에 모은다.

2. **빠르게 판단한다.**  
   오늘 들어온 자료의 핵심 내용과 출처를 짧은 시간 안에 확인한다.

3. **중요 지식을 남긴다.**  
   중요한 자료를 직접 체크하고 메모와 묶음으로 보존한다.

4. **다시 활용한다.**  
   과거 자료와 판단을 검색하고 업무·기획·의사결정에 재사용한다.

5. **경제 환경과 함께 본다.**  
   환율·주가·금리·물가 등 외부 환경을 기업·기술·정책·투자 정보의 배경으로 확인한다.

### 2.3 제품이 답해야 하는 질문

사용자는 매일 다음 질문에 답할 수 있어야 한다.

1. 오늘 새로 들어온 기업 정보는 무엇인가?
2. 오늘 새로 들어온 기술 정보는 무엇인가?
3. 오늘 새로 들어온 정책 정보는 무엇인가?
4. 오늘 새로 들어온 투자 정보는 무엇인가?
5. 이 중 내가 중요하다고 판단한 지식은 무엇인가?
6. 관련 자료를 이전에 어떻게 정리했는가?
7. 현재 시장·거시경제 환경은 어떠한가?

## 3. 기본 전제

| 항목 | 전제 |
|---|---|
| 사용자 | 승인된 내부 사용자 2~3명 |
| 공개 범위 | 외부 공개하지 않음 |
| 수집 주기 | 기본 하루 1회, 지표별 주기 별도 |
| 자료 규모 | 초기 하루 30~100건 |
| 대상 범위 | 고정 섹터를 사전 정의하지 않음 |
| 운영 우선순위 | 단순성, 안정성, 무료·저비용 |
| 사용자 판단 | 자동 점수보다 중요 체크·메모를 우선 |
| AI | 핵심 기능이 아니며 필요성과 비용 승인 후 도입 |

### 3.1 고정 섹터를 사용하지 않는다는 의미

- 제품 가입이나 수집 시작 전에 특정 섹터를 선택하지 않는다.
- `sectorKey`를 모든 기업·카드의 필수 조건으로 사용하지 않는다.
- 기업·기술·정책·투자 자료는 승인된 소스와 검색 조건으로 수집한다.
- 카드 유형은 MVP에서 소스별 기본값으로 부여하고, 오분류만 관리자가 수동 교정한다.
- 자동 유형 분류는 실제 오분류 규모가 확인된 뒤 후속 검토한다.
- 사용자는 키워드·출처·묶음·중요 체크를 이용해 필요한 범위를 구성한다.
- 향후 태그나 주제를 추가할 수 있지만 무거운 온톨로지나 관계 그래프를 선행하지 않는다.

## 4. 정보 범위

### 4.1 기업 정보

초기 수집 후보:

- 투자 유치
- 신제품·서비스 출시
- 사업 확장·철수
- 제휴·계약
- 인수합병
- 주요 인사

- 실적·공시

목표는 기업 명부를 관리하는 것이 아니라 기업의 새로운 움직임을 모니터링하는 것이다.

### 4.2 기술 정보

초기 수집 후보:

- 주요 기술 발표
- 연구기관·기업 기술 자료
- 산업·기술 보고서
- 논문
- 특허

논문과 특허는 독립된 대형 데이터베이스로 만들지 않는다. 사용자가 모니터링할 가치가
있는 기술 자료를 일반 카드 흐름에 포함한다.

### 4.3 정책 정보

초기 수집 후보:

- 정부 정책
- 법·규제 변경
- 지원사업
- 예산·공공계획
- 정부·공공기관 발표
- 산업 육성책

### 4.4 투자 정보

초기 수집 후보:

- 스타트업·기업 투자유치
- 벤처캐피털·CVC·PE 투자
- 신규 펀드 결성과 출자사업
- 정부·기관의 투자계획
- 전략적 지분투자
- 인수합병
- 투자기관 포트폴리오 변화
- 국내외 벤처투자 시장 동향

투자 카드는 가능한 경우 투자 대상, 투자자, 투자 단계, 투자 금액·통화와 발표일을
함께 저장한다. 확인되지 않은 금액이나 단계는 추정하지 않고 `미확인`으로 둔다.
투자 정보는 기업 명부가 아니라 자금의 흐름과 투자 움직임을 모니터링하는 독립 축이다.

## 5. 핵심 사용자 흐름

```text
Google 로그인
  → 관리자 승인
  → 오늘 화면 진입
  → 시장·거시경제 현황 확인
  → 기업·기술·정책·투자 신규 카드 훑어보기
  → 중요한 카드 체크
  → 필요하면 메모 작성
  → 관련 카드 묶음에 추가
  → 이후 검색·묶음으로 다시 활용
```

사용자는 아무것도 작성하지 않아도 새 자료와 경제 현황을 볼 수 있어야 한다.
체크·메모·묶음은 지식을 보존하고 다시 사용하기 위한 핵심 조작이다.

## 7. 카드 모델

카드는 기업·기술·정책·투자 자료를 사용자에게 보여주는 공통 단위다.

필수 필드:

| 필드 | 설명 |
|---|---|
| `id` | 카드 ID |
| `type` | `company` / `technology` / `policy` / `investment` |
| `title` | 제목 |
| `summary` | 짧은 발췌 또는 요약 |
| `source_id` | 대표 출처 |
| `source_item_id` | 원천 자료 |
| `published_at` | 발표 시각 |
| `collected_at` | 수집 시각 |
| `created_at` | 생성 시각 |
| `updated_at` | 수정 시각 |

투자 카드에는 다음 선택 필드를 추가한다.

| 필드 | 설명 |
|---|---|
| `investment_target` | 투자 대상 |
| `investors` | 확인된 투자자 목록 |
| `investment_stage` | Seed, Series A 등 확인된 투자 단계 |
| `investment_amount` | 확인된 투자 금액 |
| `investment_currency` | 금액의 통화 |

확인되지 않은 값은 비워두며 자동 추정하지 않는다.

사용자별 상태는 별도 테이블로 분리한다.

| 필드 | 설명 |
|---|---|
| `user_id` | 사용자 |
| `card_id` | 카드 |
| `important` | 중요 체크 |

### 7.1 자동 점수 정책

- 초기에는 복잡한 정보가치 모델을 제품 핵심으로 사용하지 않는다.
- 출처 신뢰도와 최신성으로 기본 정렬 보조값만 계산할 수 있다.
- 사용자에게는 자동 점수보다 중요 체크와 자료 유형을 우선 표시한다.
- 규칙 버전 관리와 품질 표본 평가는 실제 필요가 확인될 때 재검토한다.

## 8. 데이터 모델

### 8.1 유지할 핵심 테이블

- `users`
- `accounts`
- `sessions`
- `verification_tokens`
- `sources`
- `source_items`
- `cards`
- `ingestion_runs`
- `indicators`
- `indicator_values`

`cards.source_id`와 `cards.source_item_id`를 MVP 대표 출처로 사용한다.
다중 출처 연결용 `card_sources`는 후속 기능으로 두되 기존 데이터는 삭제하지 않는다.

### 8.2 새로 필요한 테이블

- `card_user_states`
- `notes`
- `collections`
- `collection_items`

사용자 상태와 지식 데이터는 다음 원칙을 따른다.

- 중요 체크는 사용자별이다.
- 메모는 사용자별로 카드당 하나만 작성·수정한다.
- 묶음은 제목과 카드 목록만 저장한다.
- `notes`는 `(user_id, card_id)` 조합을 유일하게 유지한다.

### 8.3 비활성화 또는 제거 검토 대상

- `companies`
- `company_verifications`
- `research_papers`
- `card_quality_reviews`
- `information_value_rule_versions`
- `card_value_assessments`
- `merge_candidates`

즉시 물리 삭제하지 않는다. 새 제품 흐름에서 사용하지 않도록 먼저 비활성화하고,
데이터 보존 여부를 검토한 뒤 별도 마이그레이션으로 정리한다.

## 9. 수집 구조

### 9.1 카드 자료

```text
외부 소스
  → 원문·메타데이터 수집
  → 외부 ID·URL 기준 중복 방지
  → 기업·기술·정책·투자 유형 분류
  → 카드 생성
  → 오늘 화면 노출
```

### 9.2 경제지표

```text
시장·거시 데이터 공급자
  → 값·기준일 검증
  → indicator_values 멱등 저장
  → 마지막 정상값·갱신 상태 표시
```

### 9.3 수집 실패

- 소스 하나의 실패가 다른 소스를 중단하지 않는다.
- 마지막 정상 데이터를 유지한다.
- 실패한 소스와 오류 시각을 관리자 화면에 표시한다.
- 네트워크 오류에는 제한된 재시도를 적용한다.
- 비밀키와 원문 전체를 오류 로그에 남기지 않는다.

---

## 10. 접근 정책

- 모든 제품 데이터는 승인된 내부 사용자만 접근한다.
- 익명 사용자는 로그인 화면만 접근한다.
- 신규 사용자는 `pending`이다.
- 관리자가 `active`로 승인해야 `/today`, `/archive`, `/cards`,
  `/collections`, `/dashboard`에 접근할 수 있다.
- `suspended` 사용자는 즉시 차단한다.
- 관리자 기능은 `admin` 역할만 접근한다.

접근 정책을 새로 개발하거나 별도 복원하는 작업은 이번 REBOOT 범위에 포함하지 않는다.
현재 인증·승인 기능을 재사용하며 기존 동작을 깨뜨리지 않는지만 회귀 검증한다.

### Stage 5 — 운영 안정화

- 실패 재시도·마지막 정상값
- 사용자 2~3명 실사용

## 13. 수용 기준

### 카드 수집

- 같은 수집을 3회 실행해도 동일 원천·카드가 중복 생성되지 않는다.
- 소스 하나가 실패해도 다른 소스가 계속 실행된다.
- 오늘 수집된 카드가 기업·기술·정책·투자 유형으로 표시된다.

### 사용자 지식 관리

- 사용자가 카드의 중요 상태를 변경할 수 있다.
- 카드에 사용자별 메모 하나를 작성·수정할 수 있다.
- 카드를 묶음에 추가·제거할 수 있다.
- 중요 체크·메모·묶음 정보가 재로그인 후 유지된다.

### 검색

- 제목·요약 키워드로 카드를 찾을 수 있다.
- 날짜·출처·자료 유형·중요 체크로 필터링할 수 있다.
- 특정 묶음에 포함된 카드만 필터링할 수 있다.

### 대시보드

- 각 지표에 값·증감·기준일·출처·갱신 시각이 표시된다.
- 데이터가 없는 상태와 실제값 `0`을 구분한다.
- 공급자 장애 시 마지막 정상값을 유지하고 지연 상태를 표시한다.

### 접근 회귀

- 기존 로그인·승인 동작이 REBOOT 변경 이후에도 동일하게 동작한다.

## 14. 성공 판단

초기 성공은 기능 수가 아니라 실제 사용으로 판단한다.

- 내부 사용자 2~3명이 주 3일 이상 접속한다.
- 사용자가 매일 기업·기술·정책·투자 신규 자료를 확인한다.
- 중요한 카드가 체크된다.
- 체크한 카드 일부에 메모 또는 묶음이 생성된다.
- 과거 카드를 검색해 다시 사용하는 사례가 발생한다.
- 경제지표의 기준일과 출처가 신뢰 가능하게 유지된다.

## 15. 열린 결정

Claude와 함께 검토할 항목:

1. 각 경제지표의 공식 데이터 공급자와 이용 조건
2. 기존 논문 100건과 기업 명부 데이터를 보존만 할지 삭제할지
3. 기존 정보가치 점수를 숨길지 단순 정렬 보조값으로 유지할지
4. 구현 브랜치를 `main`에 직접 통합할지 PR 검토 후 통합할지

### 15.1 Claude 리뷰로 잠정 확정한 결정

- 카드 유형: 소스 기본값 + 관리자 수동 교정
- 중요 체크: 사용자별
- 메모: 사용자별 카드당 하나
- 묶음: 제목 + 카드 목록
- 1차 경제지표: USD/KRW, KOSPI, KOSDAQ, 한국 기준금리, 소비자물가
- 원문 아카이빙: 후속
- 독립 `/dashboard`: 사용자 확정 요구에 따라 MVP 필수 유지
